## P1 · 고속 대시가 벽을 뚫거나 모서리에 끼인다

**재현 상황**　대시 속도를 올린 뒤 얇은 벽을 통과한다. 첫 충돌에서 이동을 통째로 취소하자 대각선 대시가 벽에 붙은 채 멈춘다.

![대각선 대시는 중심 x=3.5에서 벽에 닿고 수직 성분을 따라 (3.5,4)에서 끝난다.](./Image%20Archive/p01.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 2D 원형 캐릭터, 시작 중심 (0,0), 반지름 0.5, 이번 이동량 (10,4). 세로 벽은 x=4, 통과할 수 있는 쪽은 왼쪽이다. 추가 시험의 가로 벽은 y=3이며 아래쪽만 이동 가능하다. |
| **구현할 내용** | 벽은 축에 평행한 무한 경계면으로 제한한다. 시작 위치는 유효하다. 충돌 시각까지 전진하고 남은 이동에서 안쪽 법선 성분만 제거한다. 동시에 두 벽에 닿거나 접촉 상태에서 다시 움직이는 경우를 처리한다. |
| **출력** | 최종 중심, 접촉한 벽 ID와 최초 접촉 비율을 시간순으로 반환한다. |

**통과 기준**

- [ ] 세로 벽 하나면 t=0.35에 (3.5,1.4)에서 접촉하고 **(3.5,4)**에서 끝난다.
- [ ] 가로 벽도 있으면 **(3.5,2.5)**에서 끝난다. 이동량을 (7,5)로 바꾸면 두 면에 동시에 닿으며 벽 입력 순서를 뒤집어도 같다.
- [ ] 벽에 닿은 상태에서 벽 바깥으로 움직일 수 있다. 같은 이동을 10개 구간으로 나눠도 최종 좌표 차이가 0.0001 이하이며, t=0 접촉을 무한히 반복하지 않는다.

**디버그 과제**　충돌 직전 위치, 남은 이동 벡터, 제거한 법선 성분을 한 화면에 그려 어디서 이동량이 사라졌는지 확인한다.

## P2 · 회전하는 갑판에서 캐릭터가 미끄러진다

**재현 상황**　배가 회전하면 가만히 선 캐릭터가 밀리고, 점프하는 순간에는 갑판 속도가 두 번 더해진다.

![갑판이 90도 회전한 순간, 접점의 회전 속도는 원점 이동 속도와 반대 방향이다.](./Image%20Archive/p02.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 수평면의 2D 좌표, +각은 반시계 방향이다. 1초 동안 갑판 원점은 (0,0)→(2,0)으로 등속 이동하고 자세는 0°→90°로 등속 회전한다. 캐릭터의 갑판 로컬 발 위치는 (1,0)이다. |
| **구현할 내용** | 접지 중에는 로컬 접점을 갑판 자세로 월드에 변환한다. 이탈 순간에는 갑판 원점 속도와 접점의 회전 속도를 한 번 반영한다. 수직 점프와 중력은 이번 수평면 시험에서 제외한다. |
| **출력** | 접지 중 월드 위치, 이탈 순간 수평 속도, 이탈 후 0.1초 위치를 반환한다. |

**통과 기준**

- [ ] 1초 시점의 월드 발 위치는 **(2,1)**이다. 갑판에 서 있는 동안 로컬 접점은 (1,0)을 유지한다.
- [ ] 바로 그때 이탈하면 수평 속도는 **(2−π/2,0)**이다. 지난 1초의 시작·끝 위치 차를 그대로 속도로 사용하면 이 값을 얻을 수 없다.
- [ ] 이탈 후 외력이 없으면 0.1초 뒤 위치는 약 (2.04292,1)이다. 갑판이 이후 급정지해도 이미 이탈한 캐릭터의 속도는 변하지 않는다.

**디버그 과제**　갑판 원점 속도와 회전에 의한 접선 속도를 서로 다른 화살표로 표시한다.

## P3 · 지연되어 도착한 총격을 어느 시점에서 판정할까?

**재현 상황**　조준할 때는 적이 보였는데 서버가 명령을 받을 때는 이미 엄폐물 밖 다른 위치로 이동해 있다. 같은 발사 명령이 재전송되기도 한다.

![0.90초와 1.00초의 적은 사선을 벗어나지만 0.95초로 복원하면 최초 명중 x는 4.75다.](./Image%20Archive/p03.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 2D 서버 기록 시각 0.90·1.00초에서 적 원의 중심은 (5,−1)·(5,1), 반지름은 0.25다. 발사 원점 (0,0), 방향 +x, 사거리 10. 발사 시각은 서버 시간 기준 0.95초, 수신은 1.05초다. |
| **구현할 내용** | 최근 0.20초 이내의 명령만 받는다. 시각을 둘러싼 두 스냅샷에서 원 중심을 선형 복원하고 가장 가까운 교차점을 찾는다. 정적 벽도 검사하고 발사 ID별 피해는 한 번만 적용한다. 기록으로 복원할 수 없는 명령은 사유와 함께 거절한다. |
| **출력** | 발사 ID, 사용한 기록 두 개와 보간 비율, 최초 명중 대상 또는 거절 사유를 반환한다. |

**통과 기준**

- [ ] 기본 입력은 보간 비율 0.5, 적 중심 (5,0), **최초 명중점 (4.75,0)**이다. 양쪽 기록 중 하나만 쓰면 빗나간다.
- [ ] x=4에 y축 방향의 벽을 세우면 벽이 먼저 맞는다. 같은 발사 ID가 두 번 와도 피해 이벤트는 최대 1개다.
- [ ] 수신 시각이 같고 발사 시각이 0.80초이면 허용 시간 초과로 거절한다. 판정 뒤 현재 월드의 적 위치도 검사해 과거 상태가 남지 않았는지 확인한다.

**디버그 과제**　현재 위치와 복원 위치, 검사한 총알 경로를 겹쳐 그린다.

## P4 · 문이 바뀌는 동안 계산한 경로를 채택해도 될까?

**재현 상황**　문이 닫혀 우회 경로를 새로 찾았는데, 늦게 끝난 이전 탐색이 결과를 덮어써 NPC가 닫힌 문으로 돌아간다.

![닫힌 문 D–G 대신 H를 거치는 경로를 채택하고 뒤늦게 도착한 예전 요청 R1을 폐기한다.](./Image%20Archive/p04.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 양방향 간선 S–D(1), D–G(1), S–H(2), H–G(2). 지도 v1에서는 모두 열려 있고 v2에서는 D–G가 닫힌다. v1의 요청 R1 이후 v2의 R2를 보내되 완료 순서는 R2→R1이다. |
| **구현할 내용** | 각 탐색은 요청 시점의 지도를 사용한다. 지도 버전과 NPC별 최신 요청 ID를 기록하고, 도착한 결과가 현재 목적지·지도에 맞을 때만 채택한다. 실제 스레드 대신 완료 이벤트 순서를 바꿔 재현해도 된다. |
| **출력** | 각 완료 이벤트의 채택·폐기 사유, 현재 경로와 총비용을 출력한다. 간선에 진입하기 직전에도 통과 가능 여부를 검사한다. |

**통과 기준**

- [ ] R1의 계산 결과는 S–D–G, 비용 2다. 문이 닫힌 뒤 채택할 결과는 **R2의 S–H–G, 비용 4**다.
- [ ] R1이 마지막에 반환돼도 활성 경로가 바뀌지 않는다. 같은 지도에서 목적지만 바꾼 뒤 이전 요청이 도착해도 덮어쓰지 않는다.
- [ ] 활성 경로를 걷던 중 다음 간선이 닫히면 진입하지 않는다. 대체 경로가 없으면 이동을 멈추고 경로 없음 상태로 전환한다.

**디버그 과제**　지도 변경·요청·완료·경로 채택을 하나의 시간축에 기록한다.

## P5 · 카메라가 좁은 문틀을 통과하며 벽 속을 보여준다

**재현 상황**　중앙 광선 하나로 뒤쪽 벽을 검사했더니 카메라 중심은 지나가지만 화면 가장자리가 문틀을 파고든다. 장애물이 사라질 때는 카메라가 한 프레임 만에 뒤로 튄다.

![카메라 반지름 0.5와 문설주 반지름 0.3을 더한 원의 경계에서 중심 이동이 제한된다.](./Image%20Archive/p05.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 위에서 본 2D 단면이다. 피벗 (0,0), 이상적인 카메라 중심 (6,0), 카메라 반지름 0.5. 문설주 단면은 중심 (4,0.4), 반지름 0.3인 원이다. 초기 카메라 거리는 6이다. |
| **구현할 내용** | 피벗에서 희망 위치까지 원을 쓸어 최초 접촉 거리로 제한한다. 가까워질 때는 즉시 줄이고, 다시 멀어질 때만 초당 최대 2m로 복귀시킨다. 접촉을 허용하고 피벗은 장애물 밖에 둔다. |
| **출력** | 매 갱신마다 희망 거리, 충돌 기준 최대 거리, 실제 적용 거리를 출력한다. |

**통과 기준**

- [ ] 중앙선은 문설주를 빗나가지만 카메라 원은 닿는다. 허용 거리는 **4−√(0.8²−0.4²) ≈ 3.30718m**다.
- [ ] 문설주가 사라지고 0.25초가 지나면 실제 거리는 약 **3.80718m**다. 같은 시간을 다섯 프레임으로 나눠도 같다.
- [ ] 복귀 중 문설주가 다시 나타나면 그 프레임에 3.30718m 이하로 줄어든다. 두 장애물을 놓으면 입력 순서와 무관하게 더 가까운 접촉을 택한다.

**디버그 과제**　중앙선, 카메라 반지름을 더한 충돌 범위, 실제 정지점을 한 장에 표시한다.

## P6 · 공격 애니메이션이 빨라지면 타격 이벤트가 사라진다

**재현 상황**　검격 클립을 배속 재생했더니 한 프레임 안에서 지나친 타격 이벤트가 누락된다. 루프마다 같은 시각에 발동하는 발소리도 가끔 두 번 들린다.

![이번 갱신 범위 안에는 첫 루프의 두 마커와 다음 루프의 세 마커가 있다.](./Image%20Archive/p06.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 반복 길이 1초인 클립에 준비 0.2초, 타격 0.5초, 회수 0.8초 마커가 있다. 이전 누적 재생 시간은 0.45초, 프레임 경과 시간은 0.8초, 배속은 2다. |
| **구현할 내용** | 누적 재생 시간으로 (이전, 현재] 구간에 있는 모든 마커를 순회한다. 루프 인덱스는 0부터 센다. 이번 범위는 정방향 재생·일시정지·명시적 시점 이동이다. 시점 이동 자체에서는 이벤트를 발행하지 않는다. |
| **출력** | 각 이벤트의 루프 번호, 마커 이름, 누적 재생 시각을 시간순으로 반환한다. |

**통과 기준**

- [ ] 0.45→2.05 구간의 결과는 **0.5 타격, 0.8 회수, 1.2 준비, 1.5 타격, 1.8 회수**다.
- [ ] 같은 구간을 0.5에서 잘라 두 번 갱신해도 목록이 같다. 배속 0에서는 추가 이벤트가 없다.
- [ ] 2.05에서 0.4로 시점 이동하면 이벤트는 없다. 다시 0.55까지 재생하면 0번 루프 타격 하나만 나온다.

**디버그 과제**　마커마다 발생한 루프 번호를 표시해 누락과 중복을 찾는다.

## P7 · 멀리 이동한 캐릭터의 발사체가 순간이동한다

**재현 상황**　카메라 근처의 정밀도를 유지하려고 로컬 좌표의 원점을 옮겼더니 날아가던 총알의 궤적이 끊기고 속도까지 달라졌다.

![이전과 현재 위치의 숫자는 각각 10 작아지지만 두 프레임 모두 전역 궤적은 같다.](./Image%20Archive/p07.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 1차원 수평 축에서 시작하고 이후 2D로 확장한다. 전역 원점 O=1,000,000, 이전·현재 로컬 총알 위치는 9.75와 10.25, dt=0.1초다. 이번 틱 끝에 원점을 전역 +10만큼 옮긴다. |
| **구현할 내용** | 전역 위치=원점+로컬 위치 규약으로 현재 위치와 이전 프레임 위치를 같은 좌표계로 옮긴다. 속도·방향, 이미 전역으로 저장된 좌표, 부모 기준 자식 오프셋을 구분한다. |
| **출력** | 원점 이동 전후 전역 위치, 계산한 속도, 보간 비율 0.5의 렌더 위치를 로그로 남긴다. |

**통과 기준**

- [ ] 새 원점은 1,000,010, 이전·현재 로컬 위치는 **−0.25와 0.25**, 속도는 여전히 **+5m/s**다.
- [ ] 중간 프레임의 전역 위치는 이동 전후 모두 1,000,010이다. 왕복 원점 이동으로 같은 오프셋을 두 번 적용하지 않는다.
- [ ] 2D에서 원점을 (+10,−3) 옮겨도 부모에 붙은 총구의 로컬 오프셋과 발사 방향은 그대로이고, 총구의 전역 위치도 연속이다.

**디버그 과제**　한 틱의 이전·현재·렌더 좌표를 원점 변경 전후로 나란히 기록한다.

## P8 · 소리가 가장 크게 들리는 경로가 최단 경로와 다르다

**재현 상황**　옆방의 두꺼운 방음문 너머보다 먼 복도로 돌아온 소리가 더 크게 들려야 한다. 문을 열었을 때는 들리는 방향도 달라져야 한다.

![직통문으로 도달한 세기는 20이고 복도 H를 거친 소리는 48이다.](./Image%20Archive/p08.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 방을 노드로, 문을 양방향 간선으로 둔다. 전달률은 0~1이다. S–L=0.2, S–H=0.8, H–L=0.6. 음원 S의 세기는 100, 청취자는 L이다. |
| **구현할 내용** | 한 경로의 전달률은 간선 전달률의 곱이다. 여러 경로 중 가장 강한 하나만 사용한다. 반사음 합산은 제외한다. 전달률 0은 차단, 1은 무손실이다. 문 상태 변경 시 경로를 갱신한다. |
| **출력** | 도착 세기, 선택한 경로, 청취자 바로 앞의 방을 반환한다. 직전 방은 소리가 들어온 방향을 표시하는 데 쓴다. |

**통과 기준**

- [ ] 기본 입력은 **S–H–L, 세기 48**, 들어오는 쪽은 H다.
- [ ] 직통문 전달률을 0.7로 바꾸면 **S–L, 세기 70**으로 바뀐다. 모든 진입문이 막히면 0과 경로 없음을 반환한다.
- [ ] 무손실 간선으로 된 순환 통로를 추가해도 탐색이 끝난다. 같은 최대 세기의 경로가 여럿이면 그중 하나만 반환한다.

**디버그 과제**　선택된 경로를 따라 각 문을 지난 직후의 세기를 표시한다.

## P9 · 한 프레임에 여러 체크포인트를 통과한 랩타임이 틀린다

**재현 상황**　빠른 차가 한 프레임 사이에 두 게이트를 통과한다. 게이트 목록의 저장 순서에 따라 랩 완료가 누락되거나 역주행이 기록된다.

![차가 오른쪽으로 이동해 A, B, 결승선을 차례로 지나며 결승 시각은 프레임 끝보다 0.05초 빠르다.](./Image%20Archive/p09.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 2D에서 게이트 A·B·결승선 F는 x=2·6·9, y 범위 [−1,1]인 수직 선분이다. 정방향은 +x, 유효 순서는 A→B→F. 랩은 0초에 시작했고 차는 4.0→4.5초 사이 (0,0)→(10,0)으로 등속 이동한다. |
| **구현할 내용** | 이동 선분과 유효 방향으로 교차한 게이트를 찾고 프레임 내 교차 시각순으로 처리한다. 순서가 맞는 게이트만 인정한다. 이전 프레임 끝과 현재 시작이 같은 교차점이면 한 번만 처리한다. |
| **출력** | 승인된 게이트·시각 목록, 다음 목표 게이트, 완료한 랩타임을 출력한다. |

**통과 기준**

- [ ] 입력 순서가 F,B,A여도 **A 4.10초 → B 4.30초 → F 4.45초**이며 랩타임은 4.45초다.
- [ ] 이동을 B 위에서 두 프레임으로 나눠도 B는 한 번만 승인된다. 역주행하거나 y=2에서 평행하게 지나면 승인 이벤트가 없다.
- [ ] A만 승인받은 상태에서 B를 우회해 F만 통과하면 랩은 끝나지 않고 다음 목표는 B다.

**디버그 과제**　한 프레임에 발견한 교차 목록과 실제 승인 목록을 따로 기록한다.

## P10 · 회피 AI가 옆 차선의 적에게까지 급제동한다

**재현 상황**　현재 거리만으로 회피 대상을 고르면 가까이서 평행 이동하는 아군 때문에 멈추고, 멀리서 빠르게 다가오는 적은 놓친다.

![내 차와 A의 간격은 일정하다. 여러 칸 떨어진 B는 마주 오며 1.75초 뒤 처음 접촉한다.](./Image%20Archive/p10.svg)

| 항목 | 요구사항 |
| --- | --- |
| **입력** | 2D 원형 에이전트의 위치·속도·반지름과 예측 시간 3초. 내 위치 (0,0), 속도 (2,0), 반지름 0.5. A는 (0,2)·속도 (2,0), B는 (8,0)·속도 (−2,0)이며 반지름은 각각 0.5다. |
| **구현할 내용** | 현재 속도가 유지된다고 가정해 시간 창 안에서 실제로 접촉할 후보를 찾는다. 월드에 균일 격자를 두고 이동 중 지나갈 범위까지 고려해 후보를 줄인다. 현재 칸만 검사하는 방식과 전수 검사 결과를 비교한다. |
| **출력** | 가장 먼저 접촉할 ID와 시간, 정밀 검사를 수행한 후보 수를 반환한다. 접촉 시각 동률이면 ID 오름차순, 이미 닿았으면 0초다. |

**통과 기준**

- [ ] A는 가깝지만 평행 이동하므로 제외되고 **B, 1.75초**가 선택된다. 예측 창을 1초로 줄이면 대상이 없다.
- [ ] 격자 한 변을 2m로 두어 시작점이 여러 칸 떨어진 B도 놓치지 않는다. B를 (8,1)로 옮기면 2초의 접선 접촉도 잡힌다.
- [ ] 고정 시드로 만든 희소 장면 100개에서 전수 검사와 ID·시각이 일치한다(시간 오차 0.0001초). 후보 수를 기록하고, 먼 정지 객체만 추가한 장면에서 정밀 검사 수가 전체 객체 수보다 작은지 확인한다.

**디버그 과제**　예측 경로, 격자가 고른 후보, 실제 접촉 후보를 서로 구분해 표시한다.
