## B1 · 움직이는 적을 맞히려면 어디에 쏴야 할까?

![적이 위로 3m 갈 동안 포탄은 대각선으로 5m 이동한다.](./Image%20Archive/b1.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | 포탑 (0,0), 적 (4,0), 적 속도 (0,3), 포탄 속력 5. 조준과 발사는 즉시 이뤄진다. |
| **1일차 · 설계** | 두 물체가 같은 시각에 같은 위치에 있을 조건을 쓰고, 미래의 해가 여러 개이거나 없는 경우를 구분한다. |
| **2일차 · 구현할 내용** | 포탑은 고정, 적은 등속 이동, 포탄은 직진한다. 가장 이른 양의 명중 시간과 조준점을 반환한다. |

**통과 기준**

- [ ] **1초 뒤 (4,3)**에서 맞는다.
- [ ] 적 속도가 (6,0)이면 요격할 수 없다.
- [ ] 적 속도가 (−5,0)이면 0.4초 뒤 (2,0)에서 만난다.

## B2 · 회복 장판 하나로 몇 명까지 살릴 수 있을까?

![A와 B가 경계에 있고 C가 안에 들어오며 D는 범위 밖에 있다.](./Image%20Archive/b2.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | 아군 점 좌표 목록, 장판 반지름 2. 장판 중심은 어디에나 놓을 수 있고 경계도 포함한다. |
| **1일차 · 설계** | 아군 위치만 후보로 놓으면 놓치는 배치를 그린다. 두 아군을 동시에 장판 경계에 놓는 중심의 개수를 거리별로 구분한다. |
| **2일차 · 구현할 내용** | 최대 회복 인원과 가능한 중심 하나를 반환한다. 빈 목록은 0명·중심 없음으로 처리한다. |

**통과 기준**

- [ ] (0,0), (4,0), (2,1), (8,0)이면 **중심 (2,0), 3명**이다.
- [ ] 한 명만 있거나 두 아군이 5m 떨어져 있으면 최대 인원은 1이다.
- [ ] 반환한 중심에서 범위 안의 아군을 다시 세면 보고한 인원과 같다.

## B3 · 적이 가장 늦게 도착할 부활 지점은 어디일까?

![E1에서 B로 직행하면 7초지만 E2에서 C를 거치면 5초다.](./Image%20Archive/b3.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | 적 시작 방 E1·E2, 후보 A·B·C. 양방향 통로는 E1—A(2초), E1—B(7초), E2—C(1초), C—B(4초)다. |
| **1일차 · 설계** | 각 방에 어떤 적이든 최초로 도착할 시간을 적고, 적을 한 명씩 탐색하는 방식과 동시에 출발시키는 방식을 비교한다. |
| **2일차 · 구현할 내용** | 후보별 최초 도착 시간과 가장 안전한 후보를 반환한다. 도달 불가능한 후보가 최우선이며 동률이면 어느 쪽이든 허용한다. |

**통과 기준**

- [ ] A·B·C의 안전 시간은 2·5·1초이며 **B**가 선택된다.
- [ ] 외딴 방 D를 후보에 추가하면 D가 선택된다.
- [ ] 적이나 통로의 입력 순서를 바꿔도 후보별 시간은 같다.

## B4 · 회전하는 검이 프레임 사이에 누구를 베었을까?

![A만 각도 범위 안에 있고 검의 길이보다 가깝다.](./Image%20Archive/b4.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | 고정된 어깨, 길이 2m인 검, 시작 350°, 회전량 +30°. 적은 점이며 각도는 +x에서 반시계 방향이 양수다. |
| **1일차 · 설계** | 검이 훑은 영역을 그리고 거리와 각도 조건을 나눈다. 0°를 시계 방향으로 통과하는 예제도 만든다. |
| **2일차 · 구현할 내용** | 시작·끝 자세를 포함해 이번 회전에 한 번이라도 닿은 적 ID를 모두 반환한다. |

**통과 기준**

- [ ] A(거리 1.5·방향 0°), B(1·180°), C(2.5·10°) 중 **A만 피격**된다.
- [ ] 20°에서 −30° 회전해도 세 적 중 A만 맞는다.
- [ ] 거리 2·방향 20°인 적을 추가하면 첫 예제의 마지막 자세에서 검 끝에 맞는다.

## B5 · 벽에 두 번 튕긴 레이저는 어디서 끝날까?

![출발점에서 오른쪽 벽, 왼쪽 벽을 차례로 방문한 뒤 방 안에서 끝난다.](./Image%20Archive/b5.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | 방 [0,10]×[0,6], 내부 시작점, 영벡터가 아닌 방향, 총길이. 예시는 (2,3)에서 오른쪽으로 25m다. |
| **1일차 · 설계** | 다음 벽과 남은 거리를 비교한다. 꼭짓점에 닿는 경우와 반사 직후 같은 벽에 다시 걸리는 경우를 구분한다. |
| **2일차 · 구현할 내용** | 시작점·반사점·종점을 순서대로 반환한다. 꼭짓점에서는 두 방향 성분을 동시에 반전한다. |

**통과 기준**

- [ ] **(2,3) → (10,3) → (0,3) → (7,3)**이며 구간 길이의 합은 25다.
- [ ] (2,3)에서 위로 4m 쏘면 (2,6)을 거쳐 (2,5)에서 끝난다.
- [ ] (8,4)에서 방향 (1,1)로 4√2m 쏘면 (10,6)을 한 번 거쳐 (8,4)로 돌아온다.

## B6 · 빠르게 움직이는 두 캐릭터가 서로 통과했을까?

![두 원이 t=0.5에 만났을 때 중심 사이 거리는 반지름 합인 2m다.](./Image%20Archive/b6.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | 두 원의 반지름은 각각 1. 중심은 한 프레임 동안 A가 (0,0)→(10,0), B가 (8,0)→(6,0)으로 이동한다. |
| **1일차 · 설계** | 한 원을 고정한 좌표계에서 상대 경로를 그린다. 접촉 순간의 중심 거리와 가능한 시간 범위를 식으로 쓴다. |
| **2일차 · 구현할 내용** | 등속 이동하는 두 원의 최초 접촉 비율 t∈[0,1]을 반환한다. 처음부터 겹치거나 닿으면 0, 접촉이 없으면 별도 결과를 반환한다. |

**통과 기준**

- [ ] **t=0.5**에 중심이 (5,0)과 (7,0)에서 처음 접한다.
- [ ] 처음 3m 떨어져 같은 속도로 움직이면 접촉하지 않는다.
- [ ] 중심 거리가 1에서 시작하면 이후 멀어져도 결과는 0이다.

## B7 · 재장전이 있는 무기의 실제 화력은 얼마일까?

![마지막 탄 직후 2초 동안 재장전한다. 4초의 발사는 측정 밖이다.](./Image%20Archive/b7.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | 발사 간격 0.5초, 탄창 3발, 재장전 2초, 탄당 피해 10, 측정 시간 T=4초. 모든 탄이 명중한다. |
| **1일차 · 설계** | 가득 찬 탄창으로 0초에 첫 발을 쏜다. 마지막 탄 발사 즉시 재장전을 시작하고 재장전 완료 즉시 다음 탄을 쏘는 시간표를 그린다. |
| **2일차 · 구현할 내용** | [0,T)의 발사 시각 목록·총피해·평균 DPS를 출력한다. 한 프레임에 여러 발이 발사되는 경우도 처리한다. |

**통과 기준**

- [ ] 발사 시각은 **0, 0.5, 1, 3, 3.5초**, 총피해 50, 평균 12.5 DPS다.
- [ ] 정확히 4초에 나가는 탄은 측정에서 제외된다.
- [ ] 프레임 간격을 0.1초에서 1초로 바꿔도 목록이 같다.

## B8 · 두 플레이어를 화면 안에 담을 수 있을까?

![예시 카메라 중심 (6,3)에서 가로 10 세로 5 화면에 두 플레이어와 여백이 들어간다.](./Image%20Archive/b8.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | 맵 [0,20]×[0,10], 플레이어 (2,2)와 (10,4), 사방 여백 1m, 화면 비율 2:1. 회전 없는 직교 카메라다. |
| **1일차 · 설계** | 두 플레이어와 여백을 감싸는 사각형을 구하고 화면 비율을 적용한다. 맵 안에서 허용되는 카메라 중심 범위를 그린다. |
| **2일차 · 구현할 내용** | 최소 화면 높이와 가능한 중심 하나를 반환한다. 여백과 맵 경계를 동시에 만족할 수 없으면 실패를 반환한다. |

**통과 기준**

- [ ] 최소 크기는 **가로 10·세로 5**, 가능한 중심 하나는 **(6,3)**이다.
- [ ] 한 플레이어가 (0,0)에 서면 실패한다.
- [ ] 두 위치가 (1,1), (1,5)이면 가로 12·세로 6, 중심 (6,3)이 가능하다.

## B9 · 폭발이 연쇄될 때 각 폭탄은 언제 터질까?

![먼저 터진 폭탄의 신호가 B와 C의 예약 시각을 차례로 앞당긴다.](./Image%20Archive/b9.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | A·B·C는 같은 직선의 x=0·2·4에 있다. 반경은 각각 2.1, 예정 폭발 시각은 0·9·8초, 점화 지연은 0.5초다. |
| **1일차 · 설계** | 폭탄별 반경 안의 이웃으로 점화 신호를 그린다. 새 신호가 기존 예약보다 빠를 때 어느 시각을 쓸지 정한다. |
| **2일차 · 구현할 내용** | 경계도 포함해 폭발 신호를 전파하고 각 폭탄이 가장 빠른 시각에 한 번만 터지도록 한다. 실제 시각을 ID별로 반환한다. |

**통과 기준**

- [ ] 예시에서 A·B·C는 **0·0.5·1초**에 폭발한다.
- [ ] C의 원래 예정 시각만 0.7초로 바꾸면 C는 0.7초에 터진다.
- [ ] 기본 예시에서 B의 반경만 1로 줄이면 C는 8초에 터진다. 입력 순서를 바꿔도 같다.

## B10 · 경비가 벽 너머의 플레이어를 발견할까?

![경비와 플레이어 사이에 있는 벽만 시야를 가린다.](./Image%20Archive/b10.svg)

| 항목 | 내용 |
| --- | --- |
| **입력** | 경비 (0,0), 정면 +x, 거리 10, 전체 시야각 90°. 플레이어 (6,0), 벽 선분 (3,−1)→(3,1). |
| **1일차 · 설계** | 거리·각도·가림을 분리해 그린다. 경비 뒤와 플레이어 뒤의 벽이 판정에 미치는 영향을 비교한다. |
| **2일차 · 구현할 내용** | 거리→각도→가림 순으로 검사해 거리 밖·시야각 밖·벽에 가림·보임 중 하나를 반환한다. 시야 경계를 포함하며 두 사람 사이에서 벽 끝에 닿아도 가린다. |

**통과 기준**

- [ ] 예시에서는 **벽에 가림**, 같은 벽을 x=8로 옮기면 **보임**이다.
- [ ] 플레이어 (3,4)는 시야각 밖이고 (11,0)은 거리 밖이다.
- [ ] 벽이 없고 플레이어가 (3,3)이면 경계 위이므로 보인다.
